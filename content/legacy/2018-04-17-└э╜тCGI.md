### 遇到的问题 {#遇到的问题}

```
apache 配置 python 模式 cgi
网上的教程一般是:
```

```plain
1. 设置 cgi 目录
    <Directory "xxxx/cgi-bin/">
        AllowOverride all
        Options Indexes FollowSymLinks ExecCGI
        Order allow,deny
        Allow from all
    </Directory>

2. 添加支持的脚本
    AddHandler cgi-script .cgi .py

3. 添加执行权限 比如创建的脚本是 test.py
    chmod +x test.py
```

#### 报错 {#报错}

```
按照上面设置 然后编辑 test.py 文件， 如下:
```

```plain
#!/usr/bin/python
# -*- coding: UTF-8 -*-
print "hello test"
```

这样写的话 访问 cgi-bin/test.py 会给一个 500 的报错，内部错误，一般考虑两部分，一是 脚本有执行错误，而是 webserver 和 cgi 交互的过程有问题，这里脚本本身是没有问题的，那就是 交互问题

### cgi 流程 {#cgi-流程}

webserver 和 cgi 交互的流程如下:

![image](http://opq6sfw87.bkt.clouddn.com/cgi.png)

上面出错的原因是因为 cgi 交互是遵循 一定标准的，参数和范围有固定的格式

```plain
cgi接口规定，cgi脚本输出的开头应该是http header
而hello test 这种字符无法被识别为任何有效的http header， 所以如果访问http://localhost/cgi-bin/test.py，会返回500错误

解决办法有两个：
1、写上http header。 header与body之间必须有一个空行，以识别前面的是header，后面的是body。 代码改成：
#!/usr/bin/python
print 'Content-Type: text/html\n\nhello test'

2、空白http header。 不写http header的情况下，apache会自动补上header。 代码改成：
#!/usr/bin/python
print '\nhello test'
```

### 拓展 {#拓展}

对于 php，很多时候是和 html 混编的，也就是把数据和样式 混到一起，最后拼成 字符串给到 webserver， 然后给到 浏览器，单纯 cgi 模式的话消耗会比较大，执行方式应该是 webserver最为父进程，fork 出来 一个子进程去 执行 cgi 拿到输出后 结束子进程，下一次请求再 fork 新的进程; 取而代之的是 fastcgi ，作为一个常驻进程存在，接收 webserver 的请求 然后给出输出 还有php-fpm 这种方式，先初始化一个 进程(线程)池，等待接收 webserver的请求
